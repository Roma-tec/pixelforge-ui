# UX-writing: правила текстов интерфейса

## Тон
Дружелюбно, но без сюсюканья. Пишем от второго лица: «Создайте проект», а не «Проект будет создан».
Ошибку объясняем вместе с решением: **что случилось + что делать**.

## Правила
| Правило | Пример |
|---|---|
| Кнопка = глагол в инфинитиве | «Экспортировать», «Создать проект» |
| Максимум 3 слова на кнопке | «Скопировать в буфер» → «В буфер» |
| Без «ОК» и «Далее» там, где можно назвать действие | «Применить фильтр» вместо «ОК» |
| Ошибки — без кода и без вины пользователя | «Не удалось открыть файл. Формат не поддерживается» |
| Пустое состояние = иконка + заголовок + объяснение + кнопка | см. раздел 7.12.2 отчёта |
| Термины едины: «холст», «слой», «маска», «пресет» | не «полотно», не «уровень» |
| Числа и единицы — через пробел | `1080 × 1080 px`, `24 px`, `2,4 МБ` |

## Формулировки типовых сообщений
| Ситуация | Текст |
|---|---|
| Успех | «Экспортировано: kreativ_1080x1080.png (2,4 МБ)» |
| Лимит тарифа | «Лимит тарифа: 20 слоёв. Апгрейд до PRO снимает ограничение» |
| Потеря соединения | «Оффлайн-режим. Изменения сохранятся локально» |
| Необратимое действие | «Очистить историю? Откат действий станет невозможен» |
| Долгая операция | «Обрабатываем 45 %» + кнопка «Отменить» |
| Пустой поиск | «Ничего не найдено. Попробуйте другой запрос» |
